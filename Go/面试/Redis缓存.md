# 如何避免缓存穿透，缓存雪崩和缓存击穿？
## 缓存击穿
**某个热点数据过期**，高并发的请求因无法命中缓存而打到数据库
措施：
1、设置缓存永不过期
2、使用分布式锁避免热key重复请求数据库
   当某个热点数据失效时，使用分布式锁保证只有一个线程去请求数据库并写入缓存，其他线程等到锁释放后从缓存中获取数据
3、设置二级缓存

## 缓存穿透
**大量的热点数据过期**
发生缓存穿透一般是因为查找数据库中不存在的数据，一般出现在如下场景：
1、恶意攻击
2、误操作（比如：拿商品id当做订单id访问订单数据）
措施：
1、限制非法请求
对数据进行合法性校验，校验不通过时，避免进一步访问缓存和数据库
2、对空值进行缓存
  后续会命中缓存
3、使用布隆过滤器

## 缓存雪崩
大量的缓存在同一时间过期或者redis宕机
原因：
1、大量的key同时过期
  1）均匀设置过期时间，过期时间加随机数
  2）加互斥锁，保证并发请求相同的key，只有一个请求访问数据库并更写入缓存，其他请求从缓存数据中获取数据
  3）使用二级缓存
  4）缓存预热
   a、在程序启动时，加载数据库到缓存中
   b、定时任务，定期更新热点数据到缓存
   c、对数据一致性和实时性不高的数据，不设置过期策略
2、构建高可用的redis集群
3、限流、降级、熔断
  对数据库的访问进行限流，通过一些降级或者直接熔断阻止请求打到数据库

# Redis的过期策略和内存淘汰策略的区别？
场景不同：
1、过期策略用于删除过期的键值对
2、内存淘汰策略是内存不足时，通过删除部分数据释放内存空间

## 过期策略
1、惰性删除（Lazy Expiration）：只有当客户端访问一个已过期的键时，Redis 才会将其删除；
2、定时删除（TTL Expiration）：通过定时任务检查过期键并进行删除。
3、周期性删除（Periodic Expiration）：周期性地扫描一部分键，删除其中已过期的键。

## 内存淘汰策略
1、LRU（Least Recently Used）:淘汰最近最少使用键值对
2、LFU（Least Frequently Used：淘汰最近最不经常使用的键值对
3、Random
4、TTL（Time To Live）：淘汰剩余存活时间最短的键值对

# Redis 的过期数据会被立马删除吗？
Redis的过期数据并不会立马删除，而是会在数据被访问的时候删除并且后台周期性任务也会随机扫描过期key进行删除

# Redis 内存满了，会发生什么？
根据内存淘汰策略，清理一部分键值对

# Redis 持久化时，对过期键会如何处理的？
不会将过期键值对持久化到磁盘，所以在持久化数据恢复时，过期数据也不会被加载到内存中

# LRU 算法和 LFU 算法有什么区别？
LRU的实现方式：在对象数据结构中新增一个额外的字段，用于记录此数据的最后一次访问时间。淘汰最久没有访问的那个
LFU的实现方式：根据数据项的访问频率来淘汰数据的

# Redis如何保证与数据库的双写一致性？
## 先更新数据还是先更新缓存？
Cache Aside策略（旁路缓存策略）
当数据更新时，先删除缓存；
当读缓存时，如果没有命中缓存，则从数据库中读取数据并更新到缓存中

双写一致性解决方案：
1、延迟双删
  先删除缓存再更新数据库，最后延迟N秒再去执行一次缓存删除（减少缓存和数据不一致的问题）
